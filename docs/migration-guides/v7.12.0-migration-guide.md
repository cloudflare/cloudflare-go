# v7.12.0 Migration Guide

## Breaking Changes

### `addressing`

#### 1. AddressMaps.Zones.Update and AddressMaps.Zones.Delete removed

**What changed:**
The `Update()` and `Delete()` methods on `AddressMaps.Zones` are removed. The `Zones` sub-resource is still wired onto `AddressMaps` but now exposes no methods at all.

**Impact:**
Any call to `client.Addressing.AddressMaps.Zones.Update()` or `.Delete()` will no longer compile.

**Removed Types:**
- `AddressMapZoneUpdateResponse` (and its `Error`, `ErrorsSource`, `Message`, `MessagesSource`, `Success`, `ResultInfo` members)
- `AddressMapZoneDeleteResponse` (and the same member set)
- `AddressMapZoneUpdateParams`
- `AddressMapZoneDeleteParams`

**Removed Methods:**
- `AddressMapZoneService.Update(ctx, addressMapID string, body AddressMapZoneUpdateParams, ...) (*AddressMapZoneUpdateResponse, error)`
- `AddressMapZoneService.Delete(ctx, addressMapID string, body AddressMapZoneDeleteParams, ...) (*AddressMapZoneDeleteResponse, error)`

**Before (v7.11.0):**
```go
res, err := client.Addressing.AddressMaps.Zones.Update(ctx, "address-map-id", addressing.AddressMapZoneUpdateParams{
    AccountID: cloudflare.F("account-id"),
    ZoneID:    cloudflare.F("zone-id"),
})
```

**After (v7.12.0):**
```go
// No direct replacement. Manage zone membership through the parent address map:
res, err := client.Addressing.AddressMaps.Edit(ctx, "address-map-id", addressing.AddressMapEditParams{
    AccountID: cloudflare.F("account-id"),
})
```

**Actions Needed:**
1. Remove all `AddressMaps.Zones.Update()` and `AddressMaps.Zones.Delete()` call sites.
2. Remove references to the four removed types.
3. Re-express zone membership changes through the parent `AddressMaps` resource.

### `browser_rendering`

#### 2. Devtools browser Connect, Launch, and Page.Get removed

**What changed:**
Three devtools methods are removed. `Devtools.Browser` retains `New()`, `Delete()`, `Protocol()`, and `Version()`. The `Devtools.Browser.Page` sub-resource now exposes no methods.

**Impact:**
Calls to the removed methods will no longer compile.

**Removed Types:**
- `DevtoolBrowserConnectParams`
- `DevtoolBrowserLaunchParams`
- `DevtoolBrowserPageGetParams`

**Removed Methods:**
- `DevtoolBrowserService.Connect(ctx, sessionID string, params DevtoolBrowserConnectParams, ...) error`
- `DevtoolBrowserService.Launch(ctx, params DevtoolBrowserLaunchParams, ...) error`
- `DevtoolBrowserPageService.Get(ctx, sessionID string, targetID string, params DevtoolBrowserPageGetParams, ...) error`

**Before (v7.11.0):**
```go
err := client.BrowserRendering.Devtools.Browser.Launch(ctx, browser_rendering.DevtoolBrowserLaunchParams{
    AccountID: cloudflare.F("account-id"),
})
```

**After (v7.12.0):**
```go
// Create the browser session instead:
session, err := client.BrowserRendering.Devtools.Browser.New(ctx, browser_rendering.DevtoolBrowserNewParams{
    AccountID: cloudflare.F("account-id"),
})
```

**Actions Needed:**
1. Replace `Launch()` with `New()` to create a browser session.
2. Remove `Connect()` and `Page.Get()` call sites; connect to the devtools endpoint directly using the session returned by `New()`.

### `cloud_connector`

#### 3. Rules is now required on RuleUpdateParams

**What changed:**
`RuleUpdateParams.Rules` is now marked `api:"required"`. It was previously optional.

**Impact:**
This is a wire-level change, not a compile-time one. Existing code continues to compile, but a `Rules` field left unset is now rejected by the API instead of being silently omitted.

**Before (v7.11.0):**
```go
// Rules could be omitted; the request would still be sent.
res, err := client.CloudConnector.Rules.Update(ctx, cloud_connector.RuleUpdateParams{
    ZoneID: cloudflare.F("zone-id"),
})
```

**After (v7.12.0):**
```go
res, err := client.CloudConnector.Rules.Update(ctx, cloud_connector.RuleUpdateParams{
    ZoneID: cloudflare.F("zone-id"),
    Rules: []cloud_connector.RuleUpdateParamsRule{{
        Enabled:     cloudflare.F(true),
        Expression:  cloudflare.F("http.request.uri.path contains \"/assets/\""),
        Provider:    cloudflare.F(cloud_connector.RuleUpdateParamsRulesProviderCloudflareR2),
        Description: cloudflare.F("Route assets to R2"),
    }},
})
```

**Actions Needed:**
1. Audit every `Rules.Update()` call site and make sure `Rules` is always populated.
2. Because this does not break the build, rely on tests or API error responses to find missed call sites.

### `dns`

#### 4. Settings.Zone nameservers changed from a struct to a union

**What changed:**
Zone nameserver settings are now modelled as a union with three variants instead of a single flat struct. This affects both the response and the edit params.

| Location | Old Type | New Type |
|----------|----------|----------|
| `SettingZoneEditResponse.Nameservers` | `SettingZoneEditResponseNameservers` | `SettingZoneEditResponseNameserversUnion` |
| `SettingZoneGetResponse.Nameservers` | `SettingZoneGetResponseNameservers` | `SettingZoneGetResponseNameserversUnion` |
| `SettingZoneEditParams.Nameservers` | `param.Field[SettingZoneEditParamsNameservers]` | `param.Field[SettingZoneEditParamsNameserversUnion]` |

The three variants are `...NameserversDNSSettingsZoneNameserversCloudflare`, `...CustomExisting`, and `...CustomSet`.

**Impact:**
Code that constructs `SettingZoneEditParamsNameservers` directly, or that reads `.NSSet` / `.Type` off the response struct, will no longer compile.

**Before (v7.11.0):**
```go
_, err := client.DNS.Settings.Zone.Edit(ctx, dns.SettingZoneEditParams{
    ZoneID: cloudflare.F("zone-id"),
    Nameservers: cloudflare.F(dns.SettingZoneEditParamsNameservers{
        NSSet: cloudflare.F(int64(1)),
        Type:  cloudflare.F(dns.SettingZoneEditParamsNameserversTypeCustomAccount),
    }),
})
```

**After (v7.12.0):**
```go
_, err := client.DNS.Settings.Zone.Edit(ctx, dns.SettingZoneEditParams{
    ZoneID: cloudflare.F("zone-id"),
    Nameservers: cloudflare.F[dns.SettingZoneEditParamsNameserversUnion](
        dns.SettingZoneEditParamsNameserversDNSSettingsZoneNameserversCustomSet{
            NameserverSetID: cloudflare.F("nameserver-set-id"),
            Type:            cloudflare.F(dns.SettingZoneEditParamsNameserversDNSSettingsZoneNameserversCustomSetTypeCustom),
        },
    ),
})
```

**Actions Needed:**
1. Pick the variant that matches your configuration and construct it explicitly.
2. Use the explicit type parameter form `cloudflare.F[...Union](...)` when assigning the field.
3. When reading responses, switch on the union variant rather than accessing fields directly.
4. Note that `CustomSet` now identifies the set by `NameserverSetID` (string) rather than `NSSet` (int64) — see the new `Settings.Account.NameserverSets` resource added in this release.

2. If the values come from variables, change their type or convert with `int64(...)`.

### `email_security`

#### 6. Phishguard.Reports.List now returns a V4 paginated array

**What changed:**
`Phishguard.Reports.List()` return type changed from `*pagination.SinglePage[PhishguardReportListResponse]` to `*pagination.V4PagePaginationArray[PhishguardReportListResponse]`.

**Impact:**
Code that declares the return value with an explicit `*pagination.SinglePage[...]` type, or that stores the `ListAutoPaging()` iterator in an explicitly typed variable, will no longer compile. Ranging over `.Result` is unaffected.

**Before (v7.11.0):**
```go
var page *pagination.SinglePage[email_security.PhishguardReportListResponse]
page, err := client.EmailSecurity.Phishguard.Reports.List(ctx, email_security.PhishguardReportListParams{
    AccountID: cloudflare.F("account-id"),
})
```

**After (v7.12.0):**
```go
var page *pagination.V4PagePaginationArray[email_security.PhishguardReportListResponse]
page, err := client.EmailSecurity.Phishguard.Reports.List(ctx, email_security.PhishguardReportListParams{
    AccountID: cloudflare.F("account-id"),
})
for _, report := range page.Result {
    fmt.Println(report)
}
```

**Actions Needed:**
1. Update explicit type declarations from `SinglePage` to `V4PagePaginationArray`.
2. `ListAutoPaging()` continues to work; only its concrete iterator type name changed.

#### 8. InvestigateRelease Bulk body changed from a bare array to an object

**What changed:**
`InvestigateReleaseBulkParams.Body []string` is replaced by `IDs param.Field[[]string]` (JSON key `ids`, required). The request body is now a JSON object `{"ids": [...]}` instead of a bare JSON array.

**Impact:**
Both a compile-time and a wire-format change. The marshalling changed from `MarshalRoot(r.Body)` to `MarshalRoot(r)`.

**Before (v7.11.0):**
```go
page, err := client.EmailSecurity.Investigate.Release.Bulk(ctx, email_security.InvestigateReleaseBulkParams{
    AccountID: cloudflare.F("account-id"),
    Body:      []string{"id-1", "id-2"},
})
// wire: ["id-1","id-2"]
```

**After (v7.12.0):**
```go
page, err := client.EmailSecurity.Investigate.Release.Bulk(ctx, email_security.InvestigateReleaseBulkParams{
    AccountID: cloudflare.F("account-id"),
    IDs:       cloudflare.F([]string{"id-1", "id-2"}),
})
// wire: {"ids":["id-1","id-2"]}
```

**Actions Needed:**
1. Replace `Body: []string{...}` with `IDs: cloudflare.F([]string{...})`.
2. Note `IDs` is wrapped in `cloudflare.F()` whereas `Body` was a plain slice.
3. If you have recorded fixtures or proxies asserting on the request body, update them for the object shape.

#### 10. SKIPPED removed from the bulk investigate status enums

**What changed:**
The `SKIPPED` value is removed from five status enums. Each dropped from 7 values to 6.

**Removed Constants:**
- `InvestigateBulkNewResponseStatusSkipped`
- `InvestigateBulkGetResponseStatusSkipped`
- `InvestigateBulkListResponseStatusSkipped`
- `InvestigateBulkListParamsStatusSkipped`
- `InvestigateBulkCancelNewResponseStatusSkipped`

**Impact:**
References to these constants no longer compile. `IsKnown()` now returns `false` for the string `"SKIPPED"`, so a server still emitting it will be treated as an unknown value.

**Before (v7.11.0):**
```go
if res.Status == email_security.InvestigateBulkGetResponseStatusSkipped {
    // handle skipped
}
```

**After (v7.12.0):**
```go
// SKIPPED is no longer a modelled status. Handle the remaining values:
switch res.Status {
case email_security.InvestigateBulkGetResponseStatusPending,
    email_security.InvestigateBulkGetResponseStatusDiscovering,
    email_security.InvestigateBulkGetResponseStatusProcessing:
    // in flight
case email_security.InvestigateBulkGetResponseStatusCompleted,
    email_security.InvestigateBulkGetResponseStatusFailed,
    email_security.InvestigateBulkGetResponseStatusCancelled:
    // terminal
}
```

**Actions Needed:**
1. Remove references to the five `...Skipped` constants.
2. Re-check any exhaustive `switch` over these enums.
3. If you still need to detect `"SKIPPED"`, compare the raw string rather than a named constant.

### `hyperdrive`

#### 13. Configs integration field renamed from Integration to Provider

**What changed:**
On every `Configs` response integration struct, the `Integration` field is renamed to `Provider` and its JSON key changed from `integration` to `provider`. The associated enum types are renamed accordingly.

| Old Type | New Type |
|----------|----------|
| `ConfigNewResponseIntegrationIntegration` | `ConfigNewResponseIntegrationProvider` |
| `ConfigUpdateResponseIntegrationIntegration` | `ConfigUpdateResponseIntegrationProvider` |
| `ConfigListResponseIntegrationIntegration` | `ConfigListResponseIntegrationProvider` |
| `ConfigEditResponseIntegrationIntegration` | `ConfigEditResponseIntegrationProvider` |
| `ConfigGetResponseIntegrationIntegration` | `ConfigGetResponseIntegrationProvider` |
| `ConfigRestartResponseIntegrationIntegration` | `ConfigRestartResponseIntegrationProvider` |
| `ConfigNewParamsBodyHyperdriveHyperdriveConfigCreateWithIntegrationIntegrationIntegration` | `...IntegrationProvider` |

**Impact:**
This is both a compile-time and a wire-format change. Code reading `.Integration` off an integration struct will no longer compile, and any code that serialises the `integration` JSON key will now send the wrong field name.

**Before (v7.11.0):**
```go
cfg, err := client.Hyperdrive.Configs.Get(ctx, "config-id", hyperdrive.ConfigGetParams{
    AccountID: cloudflare.F("account-id"),
})
if cfg.Integration.Integration == hyperdrive.ConfigGetResponseIntegrationIntegrationPlanetscale {
    // ...
}
```

**After (v7.12.0):**
```go
cfg, err := client.Hyperdrive.Configs.Get(ctx, "config-id", hyperdrive.ConfigGetParams{
    AccountID: cloudflare.F("account-id"),
})
if cfg.Integration.Provider == hyperdrive.ConfigGetResponseIntegrationProviderPlanetscale {
    // ...
}
```

**Actions Needed:**
1. Rename `.Integration` field accesses on integration structs to `.Provider`.
2. Rename the enum type and constant references (`...IntegrationIntegrationPlanetscale` becomes `...IntegrationProviderPlanetscale`).
3. Update any hand-rolled JSON that sets the `integration` key to use `provider`.

### `queues`

#### 14. MqNotificationConsumer variant removed from the Consumers unions

**What changed:**
The notification-consumer variant is removed from both the `Consumers` request and response unions. `Consumers.New()` and `Consumers.Update()` now accept only `MqWorkerConsumerRequest` and `MqHTTPConsumerRequest` as `ConsumerNewParamsBodyUnion` / `ConsumerUpdateParamsBodyUnion` members.

**Impact:**
Code constructing a notification consumer will no longer compile, and 31 exported types are removed.

**Removed Types:**
- `ConsumerMqNotificationConsumerResponse` and its `Settings`, `SettingsUnion`, `SettingsObject`, `SettingsObjectEmail`, `SettingsObjectPagerduty`, `SettingsObjectWebhook`, and `Type` members
- The `Param` equivalents of all of the above
- `ConsumerNewParamsBodyMqNotificationConsumerRequest` and its `Settings*` / `Type` members
- `ConsumerUpdateParamsBodyMqNotificationConsumerRequest` and its `Settings*` / `Type` members

**Before (v7.11.0):**
```go
_, err := client.Queues.Consumers.New(ctx, "queue-id", queues.ConsumerNewParams{
    AccountID: cloudflare.F("account-id"),
    Body: queues.ConsumerNewParamsBodyMqNotificationConsumerRequest{
        Type: cloudflare.F(queues.ConsumerNewParamsBodyMqNotificationConsumerRequestTypeNotification),
        Settings: cloudflare.F[queues.ConsumerNewParamsBodyMqNotificationConsumerRequestSettingsUnion](
            queues.ConsumerNewParamsBodyMqNotificationConsumerRequestSettingsObject{},
        ),
    },
})
```

**After (v7.12.0):**
```go
// Notification consumers are no longer supported by this API.
// Use a worker or HTTP pull consumer instead:
_, err := client.Queues.Consumers.New(ctx, "queue-id", queues.ConsumerNewParams{
    AccountID: cloudflare.F("account-id"),
    Body: queues.ConsumerNewParamsBodyMqWorkerConsumerRequest{
        ScriptName: cloudflare.F("my-worker"),
        Type:       cloudflare.F(queues.ConsumerNewParamsBodyMqWorkerConsumerRequestTypeWorker),
    },
})
```

**Actions Needed:**
1. Remove all notification-consumer construction and the removed type references.
2. Migrate those consumers to the worker or HTTP pull variants.
3. When reading consumer responses, drop any handling of the notification variant.

### `resource_tagging`

#### 15. Per-variant ResourceType enums narrowed to a single value

**What changed:**
Each tagging union variant previously accepted the full catalogue of resource types. Each variant's `ResourceType` enum is now narrowed to the single resource type that variant actually describes.

| Enum | Before | After |
| --- | --- | --- |
| `AccountTagUpdateParamsBodyResourceTaggingSetTagsRequestAccountLevelWorkerVersionResourceType` | 30 values | `worker_version` only |
| `ZoneTagUpdateParamsBodyResourceTaggingSetTagsRequestZoneLevelAccessApplicationPolicyResourceType` | 11 values | `access_application_policy` only |

**Impact:**
39 exported constants are removed (29 account-level, 10 zone-level). Code referencing any of them no longer compiles. This is a correctness tightening: the removed values were never valid for these variants.

**Before (v7.11.0):**
```go
// The worker-version variant accepted unrelated resource types.
_, err := client.ResourceTagging.AccountTags.Update(ctx, resource_tagging.AccountTagUpdateParams{
    AccountID: cloudflare.F("account-id"),
    Body: resource_tagging.AccountTagUpdateParamsBodyResourceTaggingSetTagsRequestAccountLevelWorkerVersion{
        ResourceID:   cloudflare.F("resource-id"),
        ResourceType: cloudflare.F(resource_tagging.AccountTagUpdateParamsBodyResourceTaggingSetTagsRequestAccountLevelWorkerVersionResourceTypeAIGateway),
        WorkerID:     cloudflare.F("worker-id"),
    },
})
```

**After (v7.12.0):**
```go
// Only the matching resource type remains.
_, err := client.ResourceTagging.AccountTags.Update(ctx, resource_tagging.AccountTagUpdateParams{
    AccountID: cloudflare.F("account-id"),
    Body: resource_tagging.AccountTagUpdateParamsBodyResourceTaggingSetTagsRequestAccountLevelWorkerVersion{
        ResourceID:   cloudflare.F("resource-id"),
        ResourceType: cloudflare.F(resource_tagging.AccountTagUpdateParamsBodyResourceTaggingSetTagsRequestAccountLevelWorkerVersionResourceTypeWorkerVersion),
        WorkerID:     cloudflare.F("worker-id"),
    },
})
```

**Actions Needed:**
1. If you referenced a removed constant, you were using the wrong union variant. Switch to the variant that matches your resource type.
2. For tagging an arbitrary resource type, use the general-purpose variant and its `AccountTagUpdateParamsBodyResourceType` enum, which gained a `worker_version` value.

### `shared`

#### 16. Permission group Meta reshaped from Key/Value to descriptive fields

**What changed:**
The permission group `Meta` struct changed from an opaque `{Key, Value string}` pair to a descriptive struct.

| Before | After |
| --- | --- |
| `Key string` | `Category string` |
| `Value string` | `Deprecated string` |
| | `Description string` |
| | `Editable string` |
| | `EolAt time.Time` |
| | `Label string` |
| | `Scopes string` |
| | `Visibility string` |

**Impact:**
This is the widest-reaching change in the release: 11 types across four packages.

**Affected Types:**
- `shared.MemberPoliciesPermissionGroupsMeta`
- `shared.TokenPolicyPermissionGroupsMeta`
- `shared.TokenPolicyPermissionGroupsMetaParam`
- `iam.PermissionGroupListResponseMeta`
- `iam.PermissionGroupGetResponseMeta`
- `iam.UserGroupNewResponsePoliciesPermissionGroupsMeta`
- `iam.UserGroupUpdateResponsePoliciesPermissionGroupsMeta`
- `iam.UserGroupListResponsePoliciesPermissionGroupsMeta`
- `iam.UserGroupGetResponsePoliciesPermissionGroupsMeta`
- `memberships.MembershipUpdateResponsePoliciesPermissionGroupsMeta`
- `memberships.MembershipGetResponsePoliciesPermissionGroupsMeta`

**Before (v7.11.0):**
```go
for _, pg := range token.Policies[0].PermissionGroups {
    fmt.Printf("%s = %s\n", pg.Meta.Key, pg.Meta.Value)
}
```

**After (v7.12.0):**
```go
for _, pg := range token.Policies[0].PermissionGroups {
    fmt.Printf("%s [%s] %s\n", pg.Meta.Label, pg.Meta.Category, pg.Meta.Description)
    if pg.Meta.Deprecated != "" && !pg.Meta.EolAt.IsZero() {
        fmt.Printf("  deprecated, EOL %s\n", pg.Meta.EolAt.Format(time.RFC3339))
    }
}
```

**Actions Needed:**
1. Replace `Meta.Key` / `Meta.Value` reads with the specific field you need — most `Key` uses map to `Label` or `Category`, and most `Value` uses map to `Description`.
2. `EolAt` is a `time.Time`, not a string; use `IsZero()` to test for absence.
3. `Deprecated`, `Editable`, and `Visibility` are typed `string`, not `bool`, despite reading like flags.
4. For `TokenPolicyPermissionGroupsMetaParam`, update construction sites as well as reads.

### `vectorize`

#### 17. IndexDimensionConfiguration replaced by CreateIndexConfig

**What changed:**
The `Config` field on the index response changed type from `IndexDimensionConfiguration` to the shared `CreateIndexConfig` type. The `IndexDimensionConfigurationParam` param type is unchanged and still available.

**Impact:**
Code referencing `IndexDimensionConfiguration` by name, or reading `index.Config`, will no longer compile. Request construction is unaffected: `IndexDimensionConfigurationParam` and its `IndexDimensionConfigurationMetric` constants are retained.

**Removed Types:**
- `IndexDimensionConfiguration`

**Before (v7.11.0):**
```go
var cfg vectorize.IndexDimensionConfiguration = index.Config
if cfg.Metric == vectorize.IndexDimensionConfigurationMetricCosine {
    // ...
}
```

**After (v7.12.0):**
```go
var cfg vectorize.CreateIndexConfig = index.Config
if cfg.Metric == vectorize.CreateIndexConfigMetricCosine {
    // ...
}
```

**Not affected — request construction is unchanged:**
```go
_ = vectorize.IndexDimensionConfigurationParam{
    Dimensions: cloudflare.F(int64(768)),
    Metric:     cloudflare.F(vectorize.IndexDimensionConfigurationMetricCosine),
}
```

**Actions Needed:**

```go
res, err := client.WorkersForPlatforms.Dispatch.Namespaces.Scripts.Tags.Delete(
```

### `zero_trust`

#### 19. Gateway list methods now return V4 paginated arrays

**What changed:**
Two Gateway list methods changed pagination type:

| Method | Old Return Type | New Return Type |
|--------|----------------|-----------------|
| `Gateway.Lists.Items.List()` | `*pagination.SinglePage[GatewayItem]` | `*pagination.V4PagePaginationArray[GatewayItem]` |

**Impact:**

```go
var page *pagination.SinglePage[zero_trust.GatewayItem]
```

```go
var page *pagination.V4PagePaginationArray[zero_trust.GatewayItem]
page, err := client.ZeroTrust.Gateway.Lists.Items.List(ctx, "list-id", zero_trust.GatewayListItemListParams{
    AccountID: cloudflare.F("account-id"),
})
for _, item := range page.Result {
    fmt.Println(item.Value)
}
```

**Actions Needed:**
1. Update explicit type declarations from `SinglePage` to `V4PagePaginationArray`.
2. `ListAutoPaging()` continues to work; only its concrete iterator type name changed.
