# v7.9.0 Migration Guide

## Breaking Changes

### `billing`

#### 1. Usage.Paygo and Usage.PaygoInfo endpoints changed

**What changed:**
The `Paygo()` method endpoint changed from `/accounts/{account_id}/paygo-usage` to `/accounts/{account_id}/billable-usage`. The `PaygoInfo()` method endpoint changed from `/accounts/{account_id}/paygo-usage-info` to `/accounts/{account_id}/billable-usage/info`.

**Impact:**
The method signatures and return types are unchanged. Calls will now hit the new endpoints. If your backend or mocks rely on the old paths, they must be updated.

**Actions Needed:**
1. No code changes required for callers using the SDK methods directly.
2. Update any mock servers or request interceptors that match on the old `/paygo-usage` and `/paygo-usage-info` paths.

### `hostnames`

#### 2. Settings.TLS.Get method signature and return type changed

**What changed:**
The `Get()` method now requires a `hostname` path parameter and returns a single `*Setting` instead of a paginated `*pagination.SinglePage[SettingTLSGetResponse]`. The `SettingTLSGetResponse` type and `GetAutoPaging()` method are removed. A new `List()` method provides the paginated listing behavior.

**Impact:**
Code calling `Settings.TLS.Get()` without a hostname parameter will no longer compile. Code referencing `SettingTLSGetResponse` or `GetAutoPaging()` will no longer compile.

**Removed Types:**
- `SettingTLSGetResponse`

**Removed Methods:**
- `GetAutoPaging()`

**Before (v7.8.0):**
```go
// List all TLS settings for a zone
page, err := client.Hostnames.Settings.TLS.Get(ctx, hostnames.SettingTLSGetParamsSettingIDCiphers, hostnames.SettingTLSGetParams{
    ZoneID: cloudflare.F("zone-id"),
})
for _, setting := range page.Result {
    fmt.Println(setting.Hostname)
}
```

**After (v7.9.0):**
```go
// List all TLS settings for a zone (use List)
page, err := client.Hostnames.Settings.TLS.List(ctx, hostnames.SettingTLSListParamsSettingIDCiphers, hostnames.SettingTLSListParams{
    ZoneID: cloudflare.F("zone-id"),
})
for _, setting := range page.Result {
    fmt.Println(setting.Hostname)
}

// Get a single hostname's TLS setting (use Get with hostname param)
setting, err := client.Hostnames.Settings.TLS.Get(ctx, hostnames.SettingTLSGetParamsSettingIDCiphers, "example.com", hostnames.SettingTLSGetParams{
    ZoneID: cloudflare.F("zone-id"),
})
fmt.Println(setting.Value)
```

**Actions Needed:**
1. Replace `Get()` calls that listed all settings with `List()`.
2. For single-hostname lookups, add the `hostname` parameter to `Get()`.
3. Replace `SettingTLSGetResponse` references with `SettingTLSListResponse` (for list) or `Setting` (for get).
4. Replace `GetAutoPaging()` with `ListAutoPaging()`.

### `intel`

#### 3. AttackSurfaceReport.Issues.Dismiss method removed

**What changed:**
The `Dismiss()` method has been removed from `AttackSurfaceReport.Issues`, along with `AttackSurfaceReportIssueDismissResponse` and `AttackSurfaceReportIssueDismissParams`.

**Impact:**
Code calling `Issues.Dismiss()` or referencing the removed types will no longer compile.

**Removed Types:**
- `AttackSurfaceReportIssueDismissResponse`

**Removed Methods:**
- `AttackSurfaceReport.Issues.Dismiss()`

**Actions Needed:**
1. Remove calls to `Issues.Dismiss()`. This endpoint is no longer available in the API.

### `rulesets`

#### 4. Mutating method return types changed to envelope result types

**What changed:**
Several mutating methods now return envelope result types instead of dedicated response types:

| Method | Old Return Type | New Return Type |
|--------|----------------|-----------------|
| `Rulesets.New()` | `*RulesetNewResponse` | `*RulesetNewResponseEnvelopeResult` |
| `Rulesets.Update()` | `*RulesetUpdateResponse` | `*RulesetUpdateResponseEnvelopeResult` |
| `Rulesets.Phases.Update()` | `*PhaseUpdateResponse` | `*PhaseUpdateResponseEnvelopeResult` |
| `Rulesets.Rules.New()` | `*RuleNewResponse` | `*RuleNewResponseEnvelopeResult` |
| `Rulesets.Rules.Delete()` | `*RuleDeleteResponse` | `*RuleDeleteResponseEnvelopeResult` |
| `Rulesets.Rules.Edit()` | `*RuleEditResponse` | `*RuleEditResponseEnvelopeResult` |

**Impact:**
Code referencing the old return types by name will no longer compile. The field structure of the new types may differ.

**Removed Types:**
- `RulesetNewResponse`
- `RulesetUpdateResponse`
- `PhaseUpdateResponse`
- `RuleNewResponse`
- `RuleDeleteResponse`
- `RuleEditResponse`

**Before (v7.8.0):**
```go
result, err := client.Rulesets.New(ctx, rulesets.RulesetNewParams{
    AccountID: cloudflare.F("account-id"),
    Kind:      cloudflare.F(rulesets.KindManaged),
    Name:      cloudflare.F("My Ruleset"),
    Phase:     cloudflare.F(rulesets.PhaseHTTPRequestFirewallManaged),
})
// result is *RulesetNewResponse
fmt.Println(result.ID)
```

**After (v7.9.0):**
```go
result, err := client.Rulesets.New(ctx, rulesets.RulesetNewParams{
    AccountID: cloudflare.F("account-id"),
    Kind:      cloudflare.F(rulesets.KindManaged),
    Name:      cloudflare.F("My Ruleset"),
    Phase:     cloudflare.F(rulesets.PhaseHTTPRequestFirewallManaged),
})
// result is *RulesetNewResponseEnvelopeResult
fmt.Println(result.ID)
```

**Actions Needed:**
1. Update type references from the old response types to the new `*EnvelopeResult` types.
2. Field access patterns should remain similar; verify field names against the new types.

### `zero_trust`

#### 5. ResourceLibrary.Applications.Get and Categories.Get id parameter changed from string to int64

**What changed:**
The `id` parameter on `ResourceLibrary.Applications.Get()` and `ResourceLibrary.Categories.Get()` changed from `string` to `int64`. The `ID` field on the response types also changed from `string` to `int64`.

**Impact:**
Code passing a string ID will no longer compile.

**Before (v7.8.0):**
```go
app, err := client.ZeroTrust.ResourceLibrary.Applications.Get(ctx, "123", zero_trust.ResourceLibraryApplicationGetParams{
    AccountID: cloudflare.F("account-id"),
})
fmt.Println(app.ID) // string

cat, err := client.ZeroTrust.ResourceLibrary.Categories.Get(ctx, "456", zero_trust.ResourceLibraryCategoryGetParams{
    AccountID: cloudflare.F("account-id"),
})
fmt.Println(cat.ID) // string
```

**After (v7.9.0):**
```go
app, err := client.ZeroTrust.ResourceLibrary.Applications.Get(ctx, 123, zero_trust.ResourceLibraryApplicationGetParams{
    AccountID: cloudflare.F("account-id"),
})
fmt.Println(app.ID) // int64

cat, err := client.ZeroTrust.ResourceLibrary.Categories.Get(ctx, 456, zero_trust.ResourceLibraryCategoryGetParams{
    AccountID: cloudflare.F("account-id"),
})
fmt.Println(cat.ID) // int64
```

**Actions Needed:**
1. Change string ID arguments to `int64` values (e.g. `"123"` to `123`).
2. Update any code that treats the response `ID` field as a string.

#### 6. CASB list methods now return paginated responses

**What changed:**
Three CASB list methods now return `*pagination.SinglePage[T]` instead of raw slices or single objects:

| Method | Old Return Type | New Return Type |
|--------|----------------|-----------------|
| `Casb.Applications.List()` | `*[]CasbApplicationListResponse` | `*pagination.SinglePage[CasbApplicationListResponse]` |
| `Casb.Applications.AuthMethods.List()` | `*[]CasbApplicationAuthMethodListResponse` | `*pagination.SinglePage[CasbApplicationAuthMethodListResponse]` |
| `Casb.Integrations.List()` | `*CasbIntegrationListResponse` | `*pagination.SinglePage[CasbIntegrationListResponse]` |

**Impact:**
Code that dereferences the return value as a slice or accesses fields directly will no longer compile.

**Before (v7.8.0):**
```go
apps, err := client.ZeroTrust.Casb.Applications.List(ctx, zero_trust.CasbApplicationListParams{
    AccountID: cloudflare.F("account-id"),
})
for _, app := range *apps {
    fmt.Println(app.DisplayName)
}
```

**After (v7.9.0):**
```go
page, err := client.ZeroTrust.Casb.Applications.List(ctx, zero_trust.CasbApplicationListParams{
    AccountID: cloudflare.F("account-id"),
})
for _, app := range page.Result {
    fmt.Println(app.DisplayName)
}

// Or use auto-paging:
iter := client.ZeroTrust.Casb.Applications.ListAutoPaging(ctx, zero_trust.CasbApplicationListParams{
    AccountID: cloudflare.F("account-id"),
})
for iter.Next() {
    app := iter.Current()
    fmt.Println(app.DisplayName)
}
```

**Actions Needed:**
1. Access results via `.Result` on the returned page object instead of dereferencing a slice pointer.
2. Consider using the new `ListAutoPaging()` methods for automatic pagination.

### `zones`

#### 7. CT.Alerting response types consolidated

**What changed:**
The `CT.Alerting.Edit()` and `CT.Alerting.Get()` methods now return the shared `*CTAlertingSubscription` type instead of per-method types `*CTAlertingEditResponse` and `*CTAlertingGetResponse`.

**Impact:**
Code referencing `CTAlertingEditResponse` or `CTAlertingGetResponse` by name will no longer compile.

**Removed Types:**
- `CTAlertingEditResponse`
- `CTAlertingGetResponse`

**Before (v7.8.0):**
```go
result, err := client.Zones.CT.Alerting.Edit(ctx, zones.CTAlertingEditParams{
    ZoneID: cloudflare.F("zone-id"),
})
// result is *CTAlertingEditResponse
```

**After (v7.9.0):**
```go
result, err := client.Zones.CT.Alerting.Edit(ctx, zones.CTAlertingEditParams{
    ZoneID: cloudflare.F("zone-id"),
})
// result is *CTAlertingSubscription
```

**Actions Needed:**
1. Replace `CTAlertingEditResponse` and `CTAlertingGetResponse` type references with `CTAlertingSubscription`.

## Summary

1. **billing**: `Paygo()` and `PaygoInfo()` endpoints changed to `/billable-usage` paths
2. **hostnames**: `Settings.TLS.Get()` now requires hostname param, returns `*Setting`; use `List()` for paginated listing
3. **intel**: `AttackSurfaceReport.Issues.Dismiss()` removed
4. **rulesets**: six mutating methods return `*EnvelopeResult` types instead of dedicated response types
5. **zero_trust**: `ResourceLibrary` `Get()` methods take `int64` instead of `string`
6. **zero_trust**: CASB list methods return `*pagination.SinglePage[T]` instead of raw slices
7. **zones**: `CT.Alerting` response types consolidated to `CTAlertingSubscription`
